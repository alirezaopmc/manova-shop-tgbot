# PostgreSQL Persistence & Concurrency Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Migrate `manova-shop-tgbot` from transient in-memory maps to a persistent PostgreSQL 18.4 store on the shared cluster `manova-postgres`, with ACID transactional integrity, append-only financial accounting, and crash-resilient session state.

**Architecture:** Implement a dedicated PostgreSQL adapter under `internal/adapters/postgres` implementing the `port.Store` interface and all 9 domain repositories. Schema migrations are managed via embedded `pressly/goose/v3` SQL scripts and `jackc/pgx/v5`. High-concurrency operations (wallet balance debiting, receipt approvals, invite claims) use pessimistic row locks (`SELECT ... FOR UPDATE`) and atomic compensating ledger entries on provisioning failure.

**Tech Stack:** Go 1.27.3, PostgreSQL 18.4, `github.com/jackc/pgx/v5`, `github.com/pressly/goose/v3`, Telego.

## Global Constraints
- Target PostgreSQL cluster is `manova-postgres` listening on `127.0.0.1:10000`.
- Database name is `shop`, role name is `shop`, managed via `/opt/orbit-infra/postgres/databases.tsv`.
- Zero direct push to `main` (ADR-026); all changes must land on branch `feat/postgres-store` and squash-merge via GitHub PR.
- Accounting invariant must hold strictly: $\text{Balance} \equiv \sum \text{Ledger Amounts}$.
- Append-only immutability on `shop.wallet_ledger` enforced via trigger (refuse UPDATE/DELETE).
- Maintain documentation and docstring integrity.
